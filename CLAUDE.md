# Deep Time Atlas: notes for Claude

## What this is

An informal side project: an interactive timeline of human and deep history that runs in the browser. It is used lightly in undergraduate teaching and tweaked for fun when there is time. The owner, Eduardo (a sociologist, not a software developer), is also using it to learn how to work with LLMs.

Background, current state and the ideas list are in `docs/notes.md`. Read that first.

## How to work here

- **Keep it simple.** This is not a software product. Make the smallest change that does the job. No frameworks, no npm, no new dependencies, no test suites, no CI, and no new specification documents.
- **One thing at a time.** Make the change, rebuild, check it, then stop and report.
- **Report in plain language, briefly:** what changed on the page and anything Eduardo should look at. He doesn't need to follow the code line by line, so don't walk through it unless he asks.
- **Ask before anything big:** restructuring files, changing the data format, rewriting a renderer, or touching several tabs at once.
- **Plans are a few bullets, not a staged roadmap.**
- The files in `docs/reference/` come from an earlier, more ambitious phase of the project. Use them as background on the data format and on candidate sources, not as a to-do list.

## Two rules that don't bend

1. **Never invent data.** Every date and number on the page is currently a placeholder, and the page says so. When a real value replaces one, it must come from a source Eduardo has agreed to, and you should say where each value came from. If a source doesn't give a number, leave the gap and ask. Don't fill it with a plausible guess.
2. **Show uncertainty honestly.** "No data" is drawn differently from zero, uncertain dates fade across their plausible range, and disputed things are hatched. Don't smooth any of this away to make the page look tidier.

Also: explanatory text on the page that was written with AI (marker notes, stories, About text) is labelled as such on the About tab. Write it impersonally, never in Eduardo's voice.

## Files

| File | What it is |
|---|---|
| `index.html` | The published page. GitHub Pages serves this. **Generated by the build, so don't edit it by hand.** |
| `src/page.html` | The page's HTML, CSS and JavaScript. Edit this. |
| `data/atlas.json` | Data for the Full atlas and Stories tabs: lanes, records, sources. Dates are strings with units: `"4.6 Ga"`, `"11700 b2k"`, `"3300 BCE"`, `"1760 CE"`, `"now"`. Uncertain dates are `{ "est": …, "lo": …, "hi": … }`. |
| `build.py` | `python3 build.py` merges the two into `index.html`. It stops if a date has no unit. |
| `docs/notes.md` | Background, decisions, open questions, ideas. Update it when a decision is made. |

Some data for the Human time tab lives in `src/page.html` itself: markers in `const MARKERS`, geological periods in `const HGEO`, extra hominin species in `const HEXTRA`. Story texts are in `const STORIES`.

## Page structure

Four tabs: **Human time** (its own renderer, `HV`), **Full atlas** and **Stories** (sharing one engine, `createView`), and **About**. Tabs switch with click handlers, and the address bar hash is updated where the browser allows it.

## After a change

1. Run `python3 build.py`.
2. Open `index.html` in a browser and check the tab you changed, at desktop width and at phone width. Look at the console for errors.
3. Commit with a short, plain message. Push only when Eduardo says so. The live page updates a minute or two after a push.
